Rivenside AI Planner

Making a project's context durable, so building it doesn't depend on an AI's memory.

The question

Larger builds exposed the rate limits and the memory problems. A model working from a summary that gets a little worse with every message will eventually patch whatever it can see, and say it works.

So instead of trying to give it a better memory, I tried to make memory unnecessary.

How

The Rivenside AI Planner is a set of plain text files. Nothing to install, no account, no API key. It takes a project through five stages, in order:

  1. Interview. One question at a time, every answer written down the moment it’s given.
  2. Documents. The answers become only the documents the project needs.
  3. Review. Everything is read back together, so contradictions surface before they become bugs.
  4. Plan. The build is broken into steps small enough to follow without remembering anything.
  5. Build. The steps are followed in order, with progress recorded as it goes.

Everything recorded carries a label: fact, decision, assumption, open or rejected. An assumption never becomes a fact on its own.

What it showed

It was built to get small projects done quickly. It turned out to handle full projects well, and it can one-shot a build from a one-sentence prompt.

Sunrune, a complete first chapter of a story RPG, was built with it from one simple prompt, with nobody interfering.

This website was planned with it too, and built step by step from that plan.

What it led to

It was a small tool, but it worked far beyond what it was built for, and it led to tailored repositories, which use the same approach but are each made for one kind of build. The first, for 2D pixel art RPGs, is experiment 05.
